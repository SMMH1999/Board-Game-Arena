# شبیه‌ساز راهبردهای اسپلندور

این ابزار از ریشهٔ مخزن اجرا می‌شود و برای ارزیابی راهبردها چهار عامل را پشت یک میز محلی به بازی می‌اندازد. هر عامل از اطلاعات عمومی میز و کارت‌های رزروشدهٔ خودش استفاده می‌کند. هدف همهٔ عامل‌ها بردن بازی با رسیدن به دست‌کم ۱۵ امتیاز است.

| عامل | اولویت |
| --- | --- |
| `extension` | اجرای مستقیم `advice.js` و `forecast.js` افزونه روی وضعیت شبیه‌سازی‌شده، همراه با پیش‌بینی نوبت حریف‌ها |
| `engine` | ساخت تخفیف‌های دائمی با خریدهای اقتصادی و تبدیل آن‌ها به امتیاز در پایان |
| `points` | کسب سریع پرستیژ با تأمین ژتون کارت‌های امتیازدار و رزرو هدف‌های قابل‌خرید |
| `nobles` | جمع‌آوری تخفیف‌های هم‌پوشان برای کسب امتیاز اشراف |

## اجرا

به Python 3.10 یا جدیدتر نیاز است. برای عامل `extension`، Node.js 20 یا جدیدتر لازم است. حرکت‌ها و مسابقه‌ها در پایتون اجرا می‌شوند. Node.js فقط موتور موجود افزونه را فراخوانی می‌کند. پکیج اضافی لازم نیست.

```bash
python -m simulator --games 100 --workers 4 --seed 42 --output simulator/reports/baseline
```

مسابقه‌ها میان پردازه‌ها تقسیم می‌شوند. ترتیب صندلی‌ها در هر چهار بازی یک بار کامل می‌چرخد. با بذر و نسخهٔ یکسان، تغییر تعداد پردازه‌ها حرکت‌ها و نتایج را عوض نمی‌کند. مسیر گزارش باید جدید باشد.

موتور برداشت و بازگرداندن ژتون، سقف ده ژتون، خرید با تخفیف و طلا، رزرو رو و پشت کارت، انتخاب حداکثر یک اشراف در هر نوبت و پایان دور پس از رسیدن یک بازیکن به ۱۵ امتیاز را مدل می‌کند. در تساوی امتیاز، بازیکن با کارت خریداری‌شدهٔ کمتر برنده است. در صورت برابری تعداد کارت‌ها هم، برد مشترک ثبت می‌شود. دستهٔ ۹۰ کارت و ۱۰ اشراف، دادهٔ مستقل و ثابت آزمون دارد. چیدمان اولیه با بذر مسابقه تعیین می‌شود. نتایج فقط عملکرد روی همین داده‌ها و این ترکیب حریفان را اندازه می‌گیرند. [قواعد بازی پایه](https://en.boardgamearena.com/doc/Gamehelpsplendor)

## آزمون پیش از اعمال راهبرد

برای بررسی نسخهٔ فعلی یا تغییر پیشنهادی در موتور افزونه، فرمان را روی همان نسخهٔ کد اجرا کن.

```bash
python -m simulator --games 100 --workers 4 --require-pass extension --output simulator/reports/extension-gate
```

کد خروج `0` یعنی دست‌کم ۱۰۰ مسابقه کامل شده و راهبرد نام‌برده حداقل ۷۵٪ از کل مسابقه‌های برنامه‌ریزی‌شده را به‌تنهایی برده است. تساوی و مسابقه‌ای که به سقف دور رسیده در مخرج نرخ برد می‌مانند. اگر پیشنهاد افزونه در یک نوبت به حرکت قانونی تبدیل نشود، عامل مسیر جایگزین پایتون را طی می‌کند و همان راهبرد برای آن اجرا تأیید نمی‌شود. کد `1` یعنی رد شدن و کد `2` یعنی خطای اجرا یا پیکربندی. برای نمونه، از ۱۰۱ مسابقه حداقل ۷۶ برد لازم است.

گردش‌کار GitHub Actions همین بررسی را برای تغییرات مرتبط به مقصد `main` اجرا می‌کند و گزارش را به اجرای خودش پیوست می‌کند. وضعیت بررسی همراه درخواست ادغام نمایش داده می‌شود. اجباری‌کردن آن برای ادغام به تنظیمات محافظت از برنچ `main` مربوط است.

برای آزمودن یک راهبرد تازه، JSON زیر را در فایلی مثل `candidate.json` ذخیره کن. وزن‌ها از صفر تا ۲۰ هستند. وزن `reserve` تمایل به رزرو هدف را تغییر می‌دهد.

```json
{
  "name": "my-strategy",
  "weights": {
    "points": 2.2,
    "economy": 1.3,
    "noble": 0.8,
    "reserve": 0.9
  }
}
```

```bash
python -m simulator --candidate candidate.json --replace engine \
  --games 100 --seed 20261119 --workers 4 --require-pass my-strategy \
  --output simulator/reports/my-strategy
```

عامل تازه جای یکی از چهار عامل را می‌گیرد. قالب وزن‌ها متعلق به عامل‌های پایتون است. فایل نمونهٔ راهبرد در افزونه فقط در حافظهٔ Chrome ذخیره می‌شود و موتور پیشنهاد افزونه هنوز آن را مصرف نمی‌کند.

## گزارش

| فایل | محتوا |
| --- | --- |
| `summary.md` | تعداد برد، نتیجهٔ قبولی و تعداد دور و برندهٔ هر مسابقه |
| `summary.json` | دادهٔ قابل‌خواندن برای ابزارهای خودکار، با شمار برد، تساوی، توزیع صندلی و هش فایل‌های کد |
| `decision-trees.json` | درخت تصمیم‌های اجراشده به تفکیک عامل، مرحلهٔ بازی، دلیل انتخاب و نوع حرکت، با تعداد مشاهده و تعداد در بازی‌های برده |
| `matches.jsonl.gz` | یک رکورد JSON برای هر مسابقه، شامل بذر، ترتیب صندلی، امتیازها، تمام نوبت‌ها، حرکت برگزیده و گزینه‌های ارزیابی‌شده |

آزمون قواعد و آستانهٔ قبولی با فرمان زیر اجرا می‌شود.

```bash
python -m unittest discover -s simulator/tests -v
```
